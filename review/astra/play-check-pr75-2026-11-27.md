## Findings, most serious first

1. **Should fix: slowest beginners still cannot reliably win.** `src/game/progress.ts:ghostSpeeds` floors form at 3, giving rivals 2.4 and 3.3 WPM. The requested 2–3 WPM child typing at 2.0 WPM is slower than both; race boosts might alter results but must be measured, not assumed. The new unit test actually asserts the 2.4 floor after a 2 WPM race, not a catchable rival. Consider a bounded beginner rival below the actual demonstrated speed (e.g. 1.6 WPM for a 2 WPM baseline), or explicitly define a non-speed victory route. Seed lesson speed by current input modality where possible; current max bestWpm across all lessons can punish a child switching from keyboard to touch. Verify with real races and a 2, 2.4, 3 WPM cadence.
2. **Should fix: percentage rounding at the new pass boundaries.** `passMark` uses raw accuracy; `missHint` uses displayed `pct`. If pct rounds to whole percent, 84.6% could display 85% while failing (likewise 89.6/90). Use consistent precision or disclose the actual threshold. Add exact boundary and near-boundary tests, plus persistence/unlock checks. The brief's example "88%, so close! 85% passes" is inconsistent: 88% already passes lesson 1; on later lessons the target is 90%.
3. **Should fix / teacher workflow: comma conversion is optional and only offered on one parsed line.** `classroom.ts:recount` leaves Make the class enabled even when the UI detects a likely one-line CSV. A rushed teacher may create one student rather than 30. Add a non-destructive confirmation before creating a suspected single comma-list entry, preserve genuine "Last, First" names, test mixed newline/comma paste and 30 rows. Do not silently split names.
4. **Verify lobby count and status under real concurrency.** `waitingRiders(members)` and the newly filtered eligible roster may not have the same membership (helpers not included in diff). Use one eligibility predicate for numerator and denominator, include the local rider exactly once, verify disappearance and finished-to-lobby transitions. Count is omitted when eligible.length <=1; an isolated ready child would benefit from “1 ready — waiting for another rider.” Keep separate from the deferred teacher countdown.
5. **Minor: Duneskimmer goal explanation.** `progress.ts` appends “5 faster than your start” only when goal is strictly below the fixed ceiling. Confirm capped and uncapped starts, keyboard vs touch, and consistency with actual milestone completion. A capped target should not claim a full 5 WPM gain if it is smaller.
